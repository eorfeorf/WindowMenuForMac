# Window Menu for Mac

各ウィンドウにメニューを表示し、上部メニューバーにアプリのランチャーを追加するmacOSユーティリティです。Swift / AppKit / SwiftUI製。外部ライブラリは不要です。

## 起動

ビルド済みアプリは `build/Window Menu.app` にあります。ダブルクリックして開きます。長く使う場合は、アクセシビリティを許可する前にアプリを任意の固定フォルダへ移してください。

1. 設定画面の「システム設定を開く」を押します。
2. 「プライバシーとセキュリティ → アクセシビリティ」で **Window Menu** を許可します。一覧になければ `+` からアプリを追加してください。
3. 許可後、現在のデスクトップにある各アプリの通常ウィンドウにメニューが表示されます。
4. 「下のDockを自動非表示にする」をオンにすると、下部のDockが普段は隠れます。

上部タスクバー左端の **四角が4つのアイコン** をクリックすると、検索できるアプリ一覧が開きます。右クリックすると設定、一時停止、Dockの復元、終了を開けます。設定ウィンドウを閉じても常駐します。アプリをFinderからもう一度開いても設定画面へ戻れます。

## v0.2：ひとまとまりのタスクバー

- アプリごとの独立したメニューバー項目を廃止し、1本のタスクバー内へ同じ大きさ・間隔で配置。
- 選択中はアクセント色の下線と背景、起動中は小さな印、マウスを乗せた項目はハイライト。
- Dockから取り込んだ固定アプリの順序を保持。起動中アプリは右側へ追加し、アプリを切り替えても配置を保つ。
- 固定アプリをドラッグして他の固定アプリの前へ移動。右クリックの「左へ移動」「右へ移動」や設定画面の矢印からも並べ替え可能。
- 初期表示数は自動。画面幅とノッチを考慮した幅を確保し、残りは「⌄」へまとめる。最大1〜16個の指定も可能。
- 左端のアイコンまたは「⌄」で検索付きの一覧を開く。固定済み／起動中のアプリをグリッド表示し、検索してクリックで切り替え。
- 設定画面のプレビューも実際に操作可能。上部が混み合っている場合も、ここから一覧を開ける。

v0.1の標準4個表示は自動表示へ移行します。4個以外に変更した上限、固定アプリ、Dock設定は引き継ぎます。

## できること

- **全ウィンドウに表示**：現在のSpaceで表示中の各ウィンドウにバーを追従させます。前面のウィンドウだけに限定しません。メニュー選択時に対象アプリと対象ウィンドウを前面に出し、そのウィンドウのメニュー項目を読み直します。
- **メニュー項目の操作**：公開アクセシビリティAPIから項目を取得し、選択した項目へ `AXPress` を送信します。サブメニュー、チェック状態、無効状態、文字によるショートカット表示に対応します。横幅が足りない場合は `»` に残りをまとめます。
- **上部ランチャー**：起動中アプリと固定アプリを表示します。クリックで起動・切り替え、右クリックで固定・解除・終了。表示数は自動または最大1〜16個で、全アプリは検索付き一覧にも表示されます。
- **Dockの固定アプリを取り込む**：初回起動で読み込み、設定画面から追加取り込みもできます。Dock側のアプリ一覧は変更しません。
- **Dockの復元**：自動非表示を有効にする前に元の値（未設定も含む）を保存し、無効化・通常終了時に戻します。異常終了時は次回起動で復元してから保存された設定を適用します。手動で復元したい場合は「Dockを元の設定に戻す」を押します。
- **配置と除外**：ウィンドウ上端の外側／タイトルバー下の重ね表示を選べます。アプリ単位で表示を除外できます。

## macOSの制約と現状

これは他アプリのウィンドウ内へUIを挿入する実装ではなく、独立した非アクティブ化パネルを各ウィンドウに重ねる初期実装です。元のシステムメニューは残ります。上部ランチャーも、AppleのDockプロセス自体を上へ移動するものではありません。

- 対象は **現在のSpaceに表示中で、アクセシビリティから読み取れる通常ウィンドウ** です。最小化・非表示・別Space・フルスクリーン・システムパネルは対象外です。
- ウィンドウ上側に空きがなければ、タイトルバー下にバーを重ねます。アプリのツールバーやコンテンツと重なる場合は配置変更・アプリ除外を利用してください。ウィンドウ自体の位置やサイズは変更しません。
- アプリの独自実装、動的に生成されるメニュー、開くまで更新されない無効状態には互換性の限界があります。ルートメニュー末尾の「上部の元のメニューを開く」で元のメニューに戻れます。開いたメニューをそのままウィンドウ位置へ移す機能はありません。
- Finderなどでは、通常はOptionキーなどで切り替わる代替メニュー項目も同時に表示される場合があります。
- 同一アプリで位置・サイズが完全一致し、公開情報から区別できないウィンドウは、別ウィンドウを誤操作しないよう表示を省略します。
- Dockは **自動非表示** です。画面端へポインタを置くと再表示されます。完全消去、Dockのファイル／フォルダ、ゴミ箱、最小化ウィンドウ一覧、ドラッグ＆ドロップは上部ランチャーに含みません。
- macOSがメニューバーの配置を管理します。時計やほかの常駐アプリ用に余白を確保し、ノッチ部分にかかる場合は表示数を減らします。ただし、すべての常駐アプリやアプリメニューの占有幅を取得しているわけではないため、極端に混み合ったメニューバーではタスクバー全体が隠れる場合があります。設定画面で最大表示数を減らしてください。メニューバー左側のアプリメニュー領域へ置換する機能はありません。
- Dockの設定反映時には現在のユーザーのDockを再起動するため、一時的にDockが消えて再表示されます。強制終了直後の自動復元は行わず、次回起動で復元します。ログイン時の自動起動は未実装です。
- 開発ビルドはアドホック署名で、公証されていません。更新や移動後にmacOSから再度アクセシビリティ許可が必要になる場合があります。

スクリーンレコーディング権限、管理者権限、SIPの無効化、プロセスへのコード注入は不要です。初回起動ではアクセシビリティ許可やDock設定の変更を自動実行しません。

## ビルドとテスト

macOS 13以降、Swift 5.9以降が必要です。XcodeまたはCommand Line Toolsの入ったMacで実行してください。

```sh
bash scripts/build-app.sh
open "build/Window Menu.app"
swift test
```

デバッグ版は `bash scripts/build-app.sh debug` で作成できます。配布先のCPUアーキテクチャでビルドしてください。この環境ではApple Silicon版を生成しています。

## 配布用パッケージ

Intel MacとApple Silicon Macの両方で動くユニバーサル版を作り、DMGとZIPにまとめるには次を実行します。

```sh
bash scripts/package-release.sh
```

成果物は `dist/` に作成されます。DMGを開いてアプリを「Applications」へドラッグするとインストールできます。この配布版はApple Developer IDで署名・公証されていないため、別のMacでは初回起動時にFinderからControlクリックして「開く」を選ぶ必要がある場合があります。同梱の `インストール方法.txt` に手順を記載しています。macOS 13以降が必要です。

## 構成

| ファイル | 役割 |
| --- | --- |
| `Accessibility.swift` | AX情報と画面上のウィンドウ情報の照合、0.4秒間隔の追従、アプリごとのメニューキャッシュ |
| `WindowBars.swift` | ウィンドウごとの補助パネル、前後関係の維持、メニューの折りたたみ |
| `MenuBridge.swift` | メニュー階層の取得、対象ウィンドウの確認、選択項目の実行 |
| `Launcher.swift` | 1つのステータス項目にアプリを集約、起動状態・表示幅・メニューの管理 |
| `TaskbarStripView.swift` / `LauncherDrawer.swift` | タスクバーの描画、ドラッグ並べ替え、検索付きアプリ一覧 |
| `WindowMenuCore/TaskbarLayout.swift` | 省略項目を含む表示幅の計算と固定順序の操作 |
| `AppModel.swift` / `SettingsView.swift` | 日本語の設定画面、固定アプリ、アプリごとの除外 |
| `WindowMenuCore/DockSession.swift` | Dock設定の保存・復元と失敗時の再試行 |
| `WindowMenuCore/WindowGeometry.swift` | 複数画面の座標変換、配置とウィンドウの照合 |

自動テストはシステムのDock設定を変更せず、メモリ上の保存先を使って復元・異常終了・保存失敗を検証します。その他、複数画面の座標、画面端の配置、同一位置のウィンドウの照合を検証します。

実機検証の手順と結果は [docs/VALIDATION.md](docs/VALIDATION.md) を参照してください。
